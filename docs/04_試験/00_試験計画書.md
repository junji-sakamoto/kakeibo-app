## 1. この資料の役割

試験（テスト）の**入口**です。何を・どうやって・どこまで確かめれば合格とするかを決めます。
くわしい確認項目と結果は、下の資料に分けて書いています。

| 番号 | 資料 | 内容 |
|---|---|---|

| 02 | [画面遷移試験](02_画面遷移試験.md) | 画面遷移図の遷移1〜20の確認項目と結果 |
| 03 | [非機能試験](03_非機能試験.md) | 非機能要件の確認項目と結果（AWS に公開したあとに確かめるものを含む） |
| 04 | [試験結果のまとめ](04_試験結果のまとめ.md) | 合格・不合格の数、見つかった問題 |

## 2. 目的

- [要件定義書](../../要件定義書.md) と [設計書](../02_設計/00_設計書.md) で決めたとおりに、アプリが動くことを確かめる
- [受け入れ基準](../01_要件定義/08_受け入れ基準.md)（完成の基準）を満たしているかを確かめる

## 3. 試験の種類

| 種類 | 確かめること | 道具 | 試験のプログラム | 実行のしかた |
|---|---|---|---|---|
| **E2E 試験**（画面の操作） | 画面を実際に操作して、画面・処理側・データベースが通して正しく動くか | Playwright（Edge・Chrome） | `frontend/e2e/*.spec.js` | `frontend` で `npm run test:e2e` |
| **API 試験** | 処理側の API が、API 設計書どおりの結果を返すか | Node.js の試験の道具 | `backend/tests/*.test.js` | `backend` で `npm test` |
| **データベースの試験** | テーブルの決まり（同じ名前の禁止・外部キーなど）が働くか | MySQL | `database/tests/check_rules.sql` | [データベースの手順書](../03_手順書/01_データベースの手順書.md) の「5」 |
| **性能の試験** | 記録1万件・10人同時でも3秒以内か | Node.js | `backend/scripts/perf-check.mjs` | `backend` で `npm run perf` |
| **品質チェック** | 書き方（LINT）・ビルド・アンチパターン・部品の弱点・資料と実装の食い違い | ESLint など | `tools/*.mjs` | `node tools/quality_check.mjs` |

**上のすべては、`node tools/quality_check.mjs` の1つのコマンドで、まとめて行えます**（[品質チェックの手順書](../03_手順書/04_品質チェックの手順書.md)）。

## 4. 試験の範囲

| 範囲 | 今（自分のパソコン） | AWS に公開したあと |
|---|---|---|
| 機能1〜9、画面の共通ルール、メッセージ | ○ | （公開後に、主な操作をもう一度確かめる） |
| 遷移1〜20 | ○ | （同上） |
| 非機能要件 | 自分のパソコンで確かめられるもの（速さ・安全性・使える環境 など） | AWS で動かして初めて確かめられるもの（24時間動くか・https・データの控え・費用 など） |

## 5. 試験の環境

| 項目 | 内容 |
|---|---|
| パソコン | Windows 11 Home |
| ブラウザ | Microsoft Edge・Google Chrome（版は [開発環境と版の一覧](../03_手順書/00_開発環境と版の一覧.md)） |
| スマートフォン | 実機ではなく、ブラウザで横幅を 375 にして確かめる（実機は公開後） |
| 動かし方 | データベース（Docker の MySQL 8.4.13）・処理側（Node.js）・画面側（Vite の開発用サーバー） |

## 6. 試験のデータ

- お試しデータ（カテゴリ17件・記録28件）を**変えない**ように、試験では次のものだけを使い、終わったら全部消す
  - **2099年の日付**の記録（E2E・API 試験は11月・12月、性能の試験は1月〜12月）
  - **名前が「試験用」で始まる**カテゴリ
- 試験の前後で、お試しデータの件数が変わっていないことを確かめる

## 7. 合格の基準

- すべての試験が合格すること（1つでも不合格なら、直してから試験をやり直す）
- 公開後に行う試験は、公開したあとに行い、この資料と [非機能試験](03_非機能試験.md) に結果を書く

## 8. 試験を行う時期

| 時期 | 行うこと |
|---|---|
| コミットする前 | `node tools/quality_check.mjs`（全部の試験を含む） |
| AWS に公開する前 | 同上 |
| AWS に公開したあと | [非機能試験](03_非機能試験.md) の「公開後」の項目、主な操作の確認 |

## 9. 試験で問題が見つかったとき

1. どの確認項目が、なぜ不合格かを調べる
2. 実装の不具合なら実装を直し、資料の誤りなら資料を直す（このプロジェクトでは、資料と実装が食い違っていたら「実装を正」とする）
3. 同じ問題を見落とさないように、品質チェックのスキルのレビューポイント（[SKILL.md](../../.claude/skills/quality-check/SKILL.md)）に足す
4. [試験結果のまとめ](04_試験結果のまとめ.md) に記録する
