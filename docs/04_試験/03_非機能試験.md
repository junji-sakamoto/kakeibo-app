# 非機能試験

[試験計画書（入口）](00_試験計画書.md) に戻る

[非機能要件](../01_要件定義/07_非機能要件.md) の確認項目と結果です。
**AWS に公開して初めて確かめられるもの**は、「時期」を「公開後」とし、公開したあとに結果を書きます。

- 実施日：2026年11月3日（「今」の項目）、2026年11月8日（「公開後」の項目）
- 結果：「今」の項目は**すべて合格**。「公開後」の項目は、本番環境を作って動画を撮った日（2026年11月8日、2時間ほど）に確かめた。本番環境の性能・止める合図・費用のメール・Android の実機は未実施、または一部（下の表の「結果」に理由を書いた）
- 講師への報告が README の動画とスクリーンショットになったため、要件定義 第12版で「使える時間」などの決まりを直し、この表も合わせた
- 本番環境では、主な操作（記録の登録・修正・削除、繰越、年間の集計、カテゴリ）を、動画を撮りながら確かめた（README の「動作の確認」）

## 1. 可用性

| 確認項目 | 時期 | 確かめ方 | 結果 |
|---|---|---|---|
| 本番環境を作っているあいだは、いつでも使える | 公開後 | 作ったあとと撮影の前にアドレスを開く。撮影のあいだ止まらないか | **合格**（2026年11月8日、作ってから消すまでの2時間ほど、止まらずに使えた。処理側が止まっても自動で起動し直すことは、2026年11月6日の第5段階で確かめた） |
| 止まっているのに気づいたら、その日のうちに直せる | 公開後 | 手順書のとおりに直せるか | **合格**（2026年11月8日、作るときに RDS が作れなかったこと・パスワードが食い違ったことを、その場で直した。直し方は手順書の「困ったとき」） |
| RDS の自動バックアップが1日分残る | 公開後 | `aws rds describe-db-instances --db-instance-identifier kakeibo-db --query "DBInstances[].BackupRetentionPeriod" --output text` が `1` | **合格**（`1`。7日分にすると、無料プランの制限で RDS が作れなかったので、要件を1日分に直した） |

## 2. 性能・拡張性

| 確認項目 | 時期 | 確かめ方 | 結果 |
|---|---|---|---|
| 記録1万件・1人で、一覧と合計が3秒以内 | 今 | 性能の試験（`npm run perf`）。1か月に810件ある月の一覧と合計 | **合格**（0.14秒） |
| 記録1万件・10人が同時に、一覧と合計が3秒以内 | 今 | 同上。違う月を10人が同時に | **合格**（いちばん遅いもので0.40秒） |
| 10人が同時に、カテゴリの一覧・記録の登録が3秒以内 | 今 | 同上 | **合格**（0.07秒・0.16秒） |
| 本番環境（EC2・RDS）でも3秒以内 | 公開後 | 本番環境で同じ性能の試験を行う | 未実施（性能の試験は行っていない。動画を撮ったときは、どの画面もすぐに表示された） |

- 処理側の速さを測る試験です。画面の表示にかかる時間は、E2E 試験の中で、どの画面も数秒以内に表示されることで確かめています
- 試験の数値は、2026年11月3日に自分のパソコン（Docker の MySQL）で測ったものです
