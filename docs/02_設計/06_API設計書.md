# API 設計書

[設計書（入口）](00_設計書.md) に戻る

画面側（フロントエンド）と処理側（バックエンド）の**やりとりの決まりごと（API）**をまとめます。
どの操作でどんなやりとりが起きるかは [データの流れ](05_データの流れ.md)、入力のルールは [機能要件](../01_要件定義/04_機能要件.md)、メッセージの文章は [メッセージ一覧](../01_要件定義/06_メッセージ一覧.md) を参照してください。

## 1. API とは

画面側が処理側に「お願い」を送り、処理側が「結果」を返すときの、**送り方と返し方の決まりごと**です。
お願いは、次の3つを組み合わせて表します。

| 組み合わせるもの | 意味 | 例 |
|---|---|---|
| **メソッド**（何をしてほしいか） | 下の表のどれか | `POST` |
| **パス**（何に対してか） | 処理側の中の場所 | `/api/records` |
| **本文**（必要なデータ） | JSON という形で書いたデータ | `{ "amount": 1200 }` |

| メソッド | 意味 | このアプリでの使い道 |
|---|---|---|
| `GET` | 取り出して | 一覧や1件を取り出す |
| `POST` | 新しく作って | 登録する |
| `PUT` | 書き換えて | 修正する |
| `DELETE` | 消して | 削除する |

## 2. API の一覧

| 番号 | メソッド | パス | 内容 | 使う画面 |
|---|---|---|---|---|
| API1 | `GET` | `/api/records?month=2026-11` | その月の記録の一覧と合計を取り出す | 記録一覧画面 |
| API2 | `GET` | `/api/records/{番号}` | 記録を1件取り出す | 記録入力画面（修正） |
| API3 | `POST` | `/api/records` | 記録を登録する | 記録入力画面（登録） |
| API4 | `PUT` | `/api/records/{番号}` | 記録を修正する | 記録入力画面（修正） |
| API5 | `DELETE` | `/api/records/{番号}` | 記録を削除する | 記録一覧画面 |
| API6 | `GET` | `/api/categories` | カテゴリの一覧を取り出す | カテゴリ一覧画面、記録入力画面 |
| API7 | `GET` | `/api/categories/{番号}` | カテゴリを1件と、使われている記録の件数を取り出す | カテゴリ入力画面（修正） |
| API8 | `POST` | `/api/categories` | カテゴリを登録する | カテゴリ入力画面（登録） |
| API9 | `PUT` | `/api/categories/{番号}` | カテゴリの名前を修正する | カテゴリ入力画面（修正） |
| API10 | `DELETE` | `/api/categories/{番号}` | カテゴリを削除する | カテゴリ一覧画面 |
| API11 | `GET` | `/api/health` | 処理側が動いているかを確かめる（使う人は使わない） | —（見張り用） |

- `{番号}` の所には、記録やカテゴリの番号（1以上の整数）が入る。例：`/api/records/25`
- `?month=2026-11` は、「2026年11月の分」という条件を付ける書き方

## 3. すべての API に共通する決まり

### 3-1. データの形

| 項目 | 決まり |
|---|---|
| データの形 | JSON（`{ "名前": 値 }` の形で書く、文字のデータ） |
| 文字コード | UTF-8 |
| 項目の名前 | 英語。2つの単語は、2つ目を大文字で始めてつなげる（例：`categoryId`） |
| 日付 | `"2026-11-02"` の形の文字 |
| 金額・番号 | 数（`1200`）。文字（`"1200"`）やカンマ付き（`"1,200"`）は不可 |
| 種類 | `"income"`（収入）か `"expense"`（支出） |
| アドレス | 画面側からは、同じアドレスの `/api/…` に送る（開発中は、Vite の中継の機能で処理側に届ける） |
| 安全のための設定 | すべての結果に、安全のための HTTP の設定（ヘッダー）を付ける（helmet）。使っている部品の名前（`X-Powered-By`）は返さない |

### 3-2. 結果の番号（ステータスコード）

処理側は、結果を**3けたの番号**で知らせます。番号を見れば、画面側は成功か失敗かが分かります。

| 番号 | 意味 | このアプリで返すとき |
|---|---|---|
| `200` | 成功 | 取り出し・修正が成功した |
| `201` | 作った | 登録が成功した |
| `204` | 成功（返すデータなし） | 削除が成功した |
| `400` | お願いの中身が間違っている | 入力のチェックで間違いが見つかった |
| `404` | 見つからない | その番号の記録・カテゴリがない |
| `409` | ほかのデータとぶつかる | 同じ名前のカテゴリがある、記録で使われているカテゴリを削除しようとした |
| `500` | 処理側で思わぬ問題が起きた | 上のどれにも当てはまらない |

### 3-3. 失敗したときの返し方

失敗したときは、[メッセージ一覧](../01_要件定義/06_メッセージ一覧.md) の**番号**を返します。画面側は、その番号の文章を表示します。

**項目ごとの間違い**（入力のチェック）：どの項目が、どのメッセージかを返す

```json
{
  "errors": {
    "amount": "E06",
    "memo": "E08"
  }
}
```

**項目に関係しない失敗**：メッセージの番号を1つ返す

```json
{
  "message": "E12"
}
```

- 処理側は**文章を返さず、番号だけを返す**
  - 理由：メッセージの文章を画面側の1か所だけに置くため（同じ文章を2か所に書くと、片方だけ直して食い違うことがあるため）
- 問題のくわしい内容（データベースのエラーの文章など）は**返さない**。処理側の記録（ログ）だけに残す（[データの流れ](05_データの流れ.md) の「9」を参照）

### 3-4. どの API でも起こりうる失敗

| 番号 | 本文 | 起きるとき |
|---|---|---|
| `400` | `{ "message": "S04" }` | 本文が JSON として読めない、または大きすぎる（10KB より大きい） |
| `404` | `{ "message": "S02" }` | パスの `{番号}` が1以上の整数でない、またはその番号のデータがない |
| `404` | `{ "message": "S03" }` | 決まっていないパスに送った |
| `500` | `{ "message": "S04" }` | 処理側やデータベースで思わぬ問題が起きた |

- 処理側につながらなかったときは、処理側から何も返ってこないので、画面側が自分で S01 を表示する

## 4. 記録の API

### API1 記録の一覧と合計を取り出す

`GET /api/records?month=2026-11`

**送るもの**

| 名前 | 必須 | 内容 |
|---|---|---|
| `month` | 必須 | 年月。`"2026-11"` の形。2000-01〜2099-12 |

**成功したとき**：`200`

```json
{
  "month": "2026-11",
  "totals": {
    "income": 0,
    "expense": 5200,
    "balance": -5200
  },
  "records": [
    {
      "id": 28,
      "date": "2026-11-02",
      "type": "expense",
      "categoryId": 7,
      "categoryName": "外食",
      "amount": 1200,
      "memo": "ランチ"
    }
  ]
}
```

| 名前 | 内容 |
|---|---|
| `totals.income` | 収入の合計 |
| `totals.expense` | 支出の合計 |
| `totals.balance` | 差額（収入 − 支出）。マイナスもある |
| `records` | 記録の一覧。日付の新しい順、同じ日は番号の大きい順。0件のときは `[]`（空の一覧） |
| `records[].type` | カテゴリの種類（記録そのものは種類を持たないので、カテゴリから取り出す） |

**失敗したとき**

| 番号 | 本文 | 起きるとき |
|---|---|---|
| `400` | `{ "errors": { "month": "S04" } }` | `month` がない、形が違う、範囲外（画面側は正しい年月しか送らないので、ふつうは起きない） |

### API2 記録を1件取り出す

`GET /api/records/{番号}`

**成功したとき**：`200`。中身は API1 の `records` の1件と同じ形

```json
{
  "id": 25,
  "date": "2026-11-01",
  "type": "expense",
  "categoryId": 6,
  "categoryName": "食費",
  "amount": 3500,
  "memo": "スーパーで買い物"
}
```

**失敗したとき**：`404` `{ "message": "S02" }`（その番号の記録がない）

### API3 記録を登録する

`POST /api/records`

**送るもの**（本文）

```json
{
  "date": "2026-11-02",
  "categoryId": 7,
  "amount": 1200,
  "memo": "ランチ"
}
```

| 名前 | 必須 | ルール | 間違いのときの番号 |
|---|---|---|---|
| `date` | 必須 | `"2026-11-02"` の形。実際にある日付。2000-01-01〜2099-12-31 | 空：E01、それ以外：E02 |
| `categoryId` | 必須 | 1以上の整数。その番号のカテゴリがあること | 空：E04、ない番号・整数でない（文字の "6" など）：E13 |
| `amount` | 必須 | 整数。1〜9,999,999 | 空：E05、整数でない・1未満：E06、上限より大きい：E07 |
| `memo` | 任意 | 文字。前後の空白は取り除く。100文字まで。省いたときは空の文字 | 100文字より多い・文字でない：E08 |

- 種類（収入・支出）は**送らない**。カテゴリの種類で決まるため
- 上にない名前の項目が入っていても、無視する

**成功したとき**：`201`。本文は、登録した記録（API2 と同じ形。`id` は新しく付いた番号）。あわせて、できた記録の場所を `Location: /api/records/{番号}` で返す

**失敗したとき**

| 番号 | 本文の例 | 起きるとき |
|---|---|---|
| `400` | `{ "errors": { "amount": "E06" } }` | 入力に間違いがある（間違いのある項目をすべて返す） |

### API4 記録を修正する

`PUT /api/records/{番号}`

**送るもの**：API3 と同じ（4つの項目をすべて送る）

**成功したとき**：`200`。本文は、修正した記録（API2 と同じ形）

**失敗したとき**

| 番号 | 本文の例 | 起きるとき |
|---|---|---|
| `400` | `{ "errors": { "date": "E02" } }` | 入力に間違いがある |
| `404` | `{ "message": "S02" }` | その番号の記録がない（ほかの画面で削除された） |

### API5 記録を削除する

`DELETE /api/records/{番号}`

**成功したとき**：`204`（本文なし）

**失敗したとき**：`404` `{ "message": "S02" }`（その番号の記録がない）

## 5. カテゴリの API

### API6 カテゴリの一覧を取り出す

`GET /api/categories`

**成功したとき**：`200`

```json
{
  "categories": [
    { "id": 1, "type": "income", "name": "給料" },
    { "id": 5, "type": "income", "name": "その他" },
    { "id": 6, "type": "expense", "name": "食費" }
  ]
}
```

- 並び順：種類ごとに「登録した順。ただし『その他』は一番下」（[機能要件](../01_要件定義/04_機能要件.md) の並び順のルール）。収入用・支出用に分けて表示するのは画面側

### API7 カテゴリを1件と、使われている記録の件数を取り出す

`GET /api/categories/{番号}`

**成功したとき**：`200`

```json
{
  "id": 6,
  "type": "expense",
  "name": "食費",
  "recordCount": 4
}
```

| 名前 | 内容 |
|---|---|
| `recordCount` | このカテゴリを使っている記録の件数（すべての月）。1以上なら、画面側は影響のお知らせ（N05）を表示する |

**失敗したとき**：`404` `{ "message": "S02" }`

### API8 カテゴリを登録する

`POST /api/categories`

**送るもの**（本文）

```json
{
  "type": "expense",
  "name": "ペット"
}
```

| 名前 | 必須 | ルール | 間違いのときの番号 |
|---|---|---|---|
| `type` | 必須 | `"income"` か `"expense"` | E03 |
| `name` | 必須 | 文字。前後の空白（全角の空白も）は取り除く。1〜20文字 | 空・空白だけ・文字でない：E09、20文字より多い：E10 |

**成功したとき**：`201`。本文は、登録したカテゴリ（`{ "id": 18, "type": "expense", "name": "ペット" }`）。あわせて、できたカテゴリの場所を `Location: /api/categories/{番号}` で返す

**失敗したとき**

| 番号 | 本文の例 | 起きるとき |
|---|---|---|
| `400` | `{ "errors": { "name": "E09" } }` | 入力に間違いがある |
| `409` | `{ "errors": { "name": "E11" } }` | 同じ種類に、同じ名前のカテゴリがある（名前の欄の下に表示するため、`errors` で返す） |

### API9 カテゴリの名前を修正する

`PUT /api/categories/{番号}`

**送るもの**（本文）

```json
{
  "name": "食べ物"
}
```

- 送るのは**名前だけ**。種類は変えられないので、`type` を送っても無視する

**成功したとき**：`200`。本文は、修正したカテゴリ（API8 の成功と同じ形）

**失敗したとき**

| 番号 | 本文の例 | 起きるとき |
|---|---|---|
| `400` | `{ "errors": { "name": "E10" } }` | 入力に間違いがある |
| `404` | `{ "message": "S02" }` | その番号のカテゴリがない |
| `409` | `{ "errors": { "name": "E11" } }` | 同じ種類に、同じ名前のカテゴリがある |

### API10 カテゴリを削除する

`DELETE /api/categories/{番号}`

**成功したとき**：`204`（本文なし）

**失敗したとき**

| 番号 | 本文 | 起きるとき |
|---|---|---|
| `404` | `{ "message": "S02" }` | その番号のカテゴリがない |
| `409` | `{ "message": "E12" }` | 記録で使われている（データベースの外部キーの決まりで止まる） |

## 6. 見張り用の API

### API11 処理側が動いているかを確かめる

`GET /api/health`

**成功したとき**：`200` `{ "status": "ok" }`

- データベースにもつながるかを確かめ、つながらないときは `500` `{ "message": "S04" }` を返す
- 公開したあとに、アプリが動いているかを確かめるために使う（[非機能要件](../01_要件定義/07_非機能要件.md) の「止まっていないかの確認」）
