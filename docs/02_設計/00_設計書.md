## 1. この設計書の役割

この資料は、設計の**概要と入口**です。くわしい内容は、下の資料に分けて書いています。

[要件定義書](../01_要件定義/00_要件定義書.md) で決めた「**何を作るか**」をもとに、「**どう作るか**」を決めます。

| 段階 | 決めること |
|---|---|
| 基本設計 | **どの技術を使っても変わらない部分**（画面のつながり・データの形・データの流れ・見た目） |
| 技術選定 | 基本設計をもとに、使う技術を決める |
| 詳細設計 | **技術に合わせた細かい部分**（テーブルの細かい定義・API・サーバーの組み立て） |

### 画面モック（試作品）

画面のイメージを確認するために、[画面要件](../01_要件定義/05-0_画面一覧と共通ルール.md) をもとにした**画面モック**を作りました。

| 項目 | 内容 |
|---|---|
| 場所 | [mock/index.html](../../mock/index.html)（ファイルをダブルクリックすると、ブラウザで開ける） |
| 作り方 | HTML・CSS・JavaScript だけ（本番で使う技術とは別の、確認用の試作品） |
| できること | 4つの画面の切り替え、記録・カテゴリの登録・修正・削除、入力のチェック、月の切り替え |
| 注意 | データは保存されない（再読み込みすると、お試しデータに戻る） |

### 先に進めた部分

データベースは、ER図を作ったあとに、技術選定・詳細設計・実装まで先に進めました（実際に動かして確かめるため）。
動かし方は [データベースの手順書](../03_手順書/01_データベースの手順書.md) を参照してください。

## 3. 図の書き方について

図は **Mermaid（マーメイド）** という書き方で作っています。

- 文字で書くだけで図になるので、図を直すのが簡単
- GitHub では、自動できれいな図として表示される
- VS Code で図として見るには、拡張機能「Markdown Preview Mermaid Support」が必要
