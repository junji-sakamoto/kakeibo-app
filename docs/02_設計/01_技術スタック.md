## 1. 技術の一覧

| 部品 | 使うもの | 置き換えた元 | フォルダ | 状態 |
|---|---|---|---|---|
| データベース | MySQL 8.4（マイ・エスキューエル） | PostgreSQL | `database/` | **決定** |
| 自分のパソコンでデータベースを動かす方法 | Docker（ドッカー） | — | `database/` | **決定** |
| 処理側（バックエンド） | Node.js（ノード・ジェイエス）＋ Express（エクスプレス） | Java | `backend/` | 仮 |
| 画面側（フロントエンド） | Vue.js（ビュー・ジェイエス） | React | `frontend/` | 仮 |
| 本番環境 | AWS の EC2（画面側・処理側）＋ RDS（データベース） | — | — | 課題の条件で決まり |
| ソースコードの管理 | Git・GitHub | — | — | 課題の条件で決まり |

> 「仮」のものは、基本設計が終わってから正式に決め、選んだ理由をこの資料に追加します。

### 共通の決まり

- プログラムの言語は **JavaScript（ジャバスクリプト）** に統一する（仮）
  - TypeScript は使ってよいが、分かりやすさを優先して使わない
  - JavaScript と Java は名前が似ているが、まったく別の言語
- Tailwind CSS は使わない（[課題の条件](../01_要件定義/01_課題の条件.md) を参照）
- プログラムのフォルダ名・ファイル名は英語にする（日本語の名前だとトラブルが起きやすいため）

## 3. データベース：MySQL 8.4

### 比べたもの

| 候補 | 課題の条件 | AWS RDS で使えるか | 資料の多さ | 判断 |
|---|---|---|---|---|
| **MySQL** | ○ | ○ | 多い（日本語も多い） | **採用** |
| MariaDB | ○ | ○ | MySQL より少ない | 不採用 |
| PostgreSQL | **×（課題で使えない）** | ○ | 多い | 使えない |

### 選んだ理由

- 課題の条件（PostgreSQL を使わない）を満たす
- 本番環境の AWS RDS で使える
- 利用者が多く、日本語の資料や質問の答えが見つけやすい
- 前に一度使ったことがある

### 版（バージョン）：8.4 を選んだ理由

| 候補 | 特徴 | 判断 |
|---|---|---|
| **8.4** | 長い期間、修正が提供される安定版（LTS：長期サポート版）。AWS RDS で使える | **採用** |
| 9 系 | 新しい機能がある。修正が提供される期間が短い | 不採用 |

- **自分のパソコンと本番環境（RDS）で、同じ 8.4 を使う**（版が違うと、自分のパソコンでは動いたのに本番では動かない、ということが起きるため）

## 4. 自分のパソコンでデータベースを動かす方法：Docker

### 比べたもの

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Docker** | パソコンの中に「小さな別のパソコン（コンテナ）」を作って動かす。設定をファイルに残せて、いらなくなったらきれいに消せる | **採用** |
| Windows に直接入れる | 仕組みは分かりやすいが、設定が残りにくく、消すときに手間がかかる | 不採用 |

### 選んだ理由

- 設定をファイル（`database/compose.yaml`）に書いて GitHub に残せるので、**同じ環境を何度でも作り直せる**
- MySQL を Windows にインストールしなくてよい（Docker が MySQL を用意して動かしてくれる）
- 使い終わったら、パソコンに何も残さずに消せる
- 前に一度使ったことがある
