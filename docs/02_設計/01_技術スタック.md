# 技術スタック

[設計書（入口）](00_設計書.md) に戻る

このアプリで使う技術の一覧（技術スタック）と、**選んだ理由**・**比べたもの**をまとめます。

## 2. 全体の組み合わせ

```
[ブラウザ]                     [処理側：Node.js ＋ Express]          [データベース：MySQL]
 画面側：Vue.js        ⇄        やりとりの決まりごと（API）     ⇄       mysql2 でつなぐ
 （Vite で作った画面のファイル）   で JSON という形のデータを送り合う
```

本番環境（AWS）での置き方は、公開の前に「構成設計書」で決めます。

## 3. 言語：JavaScript

### 比べたもの

| 候補 | 特徴 | 判断 |
|---|---|---|
| **JavaScript** | 画面側（ブラウザ）でも処理側でも使える。書いたものがそのまま動く | **採用** |
| TypeScript | JavaScript に「型」（この値は数字、など）を付けたもの。間違いに気づきやすいが、覚えることが増え、動かす前に変換が必要 | 不採用 |

### 選んだ理由

- **画面側と処理側を同じ言語で書ける**ので、覚えることが少なくて済む
- 初心者にとって、書いたものがそのまま動くほうが分かりやすい
- JavaScript と Java は名前が似ているが、まったく別の言語（課題で使えない Java とは別物）

## 4. 処理側：Node.js ＋ Express

### 処理側を動かす仕組みの比較

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Node.js** | JavaScript で処理側を作れる。利用者が多い | **採用** |
| Python（＋ Flask など） | 分かりやすい言語だが、画面側と別の言語になる | 不採用 |
| PHP | ウェブでよく使われるが、画面側と別の言語になる | 不採用 |
| Java（＋ Spring） | **課題で使えない** | 使えない |

### 処理側の骨組みの比較

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Express** | Node.js で一番よく使われている骨組み。仕組みが単純で、日本語の資料がとても多い | **採用** |
| Fastify | 速さを重視した骨組み。Express より資料が少ない | 不採用 |
| Hono | 新しく軽い骨組み。資料がまだ少ない | 不採用 |

### 版：Node.js は 26 系の長期サポート版（LTS）

- LTS は、長い期間、修正が提供される安定版（MySQL 8.4 を選んだのと同じ考え方）
- 2026年10月に 26 系が LTS になった。実際に使っている版は [開発環境と版の一覧](../03_手順書/00_開発環境と版の一覧.md) を参照

### 選んだ理由

- 課題の条件（Java を使わない）を満たす
- 画面側と同じ JavaScript で書ける
- 利用者が多く、日本語の資料や質問の答えが見つけやすい
- 前に一度使ったことがある

## 5. データベースとつなぐ部品：mysql2（SQL をそのまま書く）

### 比べたもの

| 候補 | 特徴 | 判断 |
|---|---|---|
| **mysql2** | SQL を自分で書いて、データベースに送る。仕組みが見えやすい | **採用** |
| Prisma・Sequelize など（ORM） | SQL を書かずに、JavaScript の書き方でデータベースを操作できる。便利だが、裏で何が起きているか見えにくい | 不採用 |

### 選んだ理由

- **SQL を学ぶ**ことも課題の目的の1つ（[要件定義書](../../要件定義書.md) の目的2）
- テーブル作成や確認用の SQL をすでに書いていて、同じ書き方をそのまま使える
- 入力された値を SQL に直接つなげずに渡す仕組み（プレースホルダー）があり、**SQL インジェクション対策**ができる（[非機能要件](../01_要件定義/07_非機能要件.md) のセキュリティ）

## 6. 画面側：Vue.js ＋ Vue Router ＋ Vite

### 画面側の骨組みの比較

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Vue.js** | React と同じ種類の道具。HTML に近い書き方ができ、日本語の資料が多く、初心者にやさしい | **採用** |
| Svelte | 書く量が少なく済む。日本語の資料が Vue.js より少ない | 不採用 |
| Angular | 大きなアプリ向け。覚えることがとても多い | 不採用 |
| 骨組みを使わない（モックと同じ書き方） | 道具は要らないが、画面が増えると書く量が多くなり、間違いも起きやすい | 不採用 |
| React | **課題で使えない** | 使えない |

### 画面側を作る道具の比較

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Vite を使う** | Vue.js の公式がすすめる作り方。画面を部品（`.vue` ファイル）に分けて書ける。直すとすぐに画面に反映される。公開用に、軽いファイルにまとめてくれる | **採用** |
| Vite を使わない（インターネット上の Vue.js を読み込むだけ） | 準備は簡単だが、部品に分けて書きにくく、大きくなると管理しにくい | 不採用 |

### 選んだ理由

- 課題の条件（React を使わない）を満たし、「React の代わり」として説明しやすい
- 画面モックで作った4つの画面を、**部品に分けて整理して作れる**（モックの `mock.js` は1つのファイルが長くなっていた）
- 画面の切り替えは、Vue.js の公式の部品である Vue Router を使う
- 処理側とのやりとりは、ブラウザに初めから入っている `fetch` を使う（部品を増やさないため）
- 見た目は、画面モックの `style.css` をもとに、CSS をそのまま書く

## 7. データベース：MySQL 8.4

### 比べたもの

| 候補 | 課題の条件 | AWS RDS で使えるか | 資料の多さ | 判断 |
|---|---|---|---|---|
| **MySQL** | ○ | ○ | 多い（日本語も多い） | **採用** |
| MariaDB | ○ | ○ | MySQL より少ない | 不採用 |
| PostgreSQL | **×（課題で使えない）** | ○ | 多い | 使えない |

### 選んだ理由

- 課題の条件（PostgreSQL を使わない）を満たす
- 本番環境の AWS RDS で使える
- 利用者が多く、日本語の資料や質問の答えが見つけやすい
- 前に一度使ったことがある

### 版（バージョン）：8.4 を選んだ理由

| 候補 | 特徴 | 判断 |
|---|---|---|
| **8.4** | 長い期間、修正が提供される安定版（LTS：長期サポート版）。AWS RDS で使える | **採用** |
| 9 系 | 新しい機能がある。修正が提供される期間が短い | 不採用 |

- **自分のパソコンと本番環境（RDS）で、同じ 8.4 を使う**（版が違うと、自分のパソコンでは動いたのに本番では動かない、ということが起きるため）

## 8. 自分のパソコンでデータベースを動かす方法：Docker

### 比べたもの

| 候補 | 特徴 | 判断 |
|---|---|---|
| **Docker** | パソコンの中に「小さな別のパソコン（コンテナ）」を作って動かす。設定をファイルに残せて、いらなくなったらきれいに消せる | **採用** |
| Windows に直接入れる | 仕組みは分かりやすいが、設定が残りにくく、消すときに手間がかかる | 不採用 |

### 選んだ理由

- 設定をファイル（`database/compose.yaml`）に書いて GitHub に残せるので、**同じ環境を何度でも作り直せる**
- MySQL を Windows にインストールしなくてよい（Docker が MySQL を用意して動かしてくれる）
- 使い終わったら、パソコンに何も残さずに消せる
- 前に一度使ったことがある

## 9. 安全のための設定：helmet

| 候補 | 特徴 | 判断 |
|---|---|---|
| **helmet** | Express で安全のための HTTP の設定（ヘッダー）をまとめて付ける部品。Express の公式の「安全のためのおすすめ」でも紹介されている | **採用** |
| 自分で1つずつ設定する | 部品は増えないが、付け忘れが起きやすい | 不採用 |

## 10. プログラムの書き方のチェック（LINT）：ESLint

| 候補 | 特徴 | 判断 |
|---|---|---|
| **ESLint** | JavaScript の書き方のチェックで、一番よく使われている道具。Vue.js の公式も、Vue.js 用の決まり（eslint-plugin-vue）を用意している | **採用** |
| チェックしない | 道具は要らないが、間違いや書き方のばらつきに気づきにくい | 不採用 |

- 決まりは、ESLint と Vue.js の公式がすすめる決まりを使い、少しだけ足している（[品質チェックの手順書](../03_手順書/04_品質チェックの手順書.md)）
- Java でよく使われる Checkstyle は Java 専用なので使えない。処理側（JavaScript）では、ESLint が Checkstyle と同じ役割をする
