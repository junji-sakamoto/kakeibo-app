# 課題の条件

[要件定義の概要（入口）](00_概要.md) に戻る

スクールの課題の条件と、このアプリを作るうえで守らなければいけない条件（制約条件）をまとめます。
条件に合わせて選んだ技術は、[技術スタック](../02_設計/01_技術スタック.md) を参照してください。

## 1. スクールの課題の条件

| 番号 | 条件 |
|---|---|
| 1 | 画面側（フロントエンド）・処理側（バックエンド）・データベースを、それぞれ作る |
| 2 | React・Java・PostgreSQL などは使わず、代わりのものを使う |
| 3 | TypeScript は使ってもよい |
| 4 | 本番環境（公開先）は、AWS の EC2 と RDS の組み合わせにする |
| 5 | 提出は GitHub の URL（アドレス）。main ブランチではなく、作業用ブランチ（develop）で作業する |

> 途中で新しい条件に気づいたら、ここに追記する。

## 2. そのほかの制約条件（自分で決めた条件）

| 番号 | 条件 | 理由 |
|---|---|---|
| 1 | AWS の費用は、月5,000円以内に収める | 個人で無理なく払える金額にするため（くわしくは [非機能要件](07_非機能要件.md)） |
| 2 | Tailwind CSS は使わない | 以前の課題の指示にあったため、念のため |

## 3. 条件を満たしているかの確認

| 条件 | どう満たすか |
|---|---|
| 3つの部品を作る | `frontend/`・`backend/`・`database/` にフォルダを分けて作る |
| React・Java・PostgreSQL を使わない | それぞれ別の技術に置き換える（[技術スタック](../02_設計/01_技術スタック.md)） |
| EC2 と RDS の組み合わせ | EC2 で画面側と処理側を動かし、RDS のデータベースにつなぐ |
| 作業用ブランチで作業する | `develop` ブランチで作業する |
