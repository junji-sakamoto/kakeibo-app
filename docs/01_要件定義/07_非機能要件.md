# 非機能要件（機能以外の決まりごと）

[要件定義の概要（入口）](00_概要.md) に戻る

## 非機能要件とは

「記録を登録できる」のような**機能**ではなく、「いつ使えるか」「どのくらい速いか」「どう守るか」といった、**品質や使い心地に関する決まりごと**です。

国の機関（IPA：情報処理推進機構）がまとめた「非機能要求グレード」という考え方にそって、次の6つの観点で決めます。最後に、使いやすさについての決まりごとも加えています。

| 観点 | ひとことで言うと |
|---|---|
| 1. 可用性 | いつ使えるか。止まったらどうするか |
| 2. 性能・拡張性 | どのくらい速いか。データが増えても大丈夫か |
| 3. 運用・保守性 | 公開したあと、どう見守り、どう直すか |
| 4. 移行性 | 古い仕組みからデータを移すか |
| 5. セキュリティ | どう守るか |
| 6. システム環境 | どんな機械・ブラウザで動かすか |
| 7. 使いやすさ | 迷わずに使えるか |

---

## 1. 可用性（いつ使えるか・止まったらどうするか）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 使える時間 | 公開期間中は **24時間・毎日** 使える | 講師がいつ確認するか分からないため |
| 止めてもよいとき | 修正版に入れ替える作業の間は、止まってもよい（事前のお知らせはしない） | 個人の課題で、利用者が限られるため |
| 止まったときに直す目標 | 止まっているのに**気づいてから1日以内**に直す | 1人で作業しているため、無理のない目標にした |
| 止まっていないかの確認 | 公開期間中は、**1日1回**、自分でアドレスを開いて確認する | 簡単に続けられる方法にした |
| データの控え（バックアップ） | RDS の自動バックアップを使い、**7日分**の控えを残す | 失敗やトラブルがあっても、データを戻せるようにするため |
| 失ってもよいデータの量 | 最大で**1日分** | データはお試し用で、控えから戻せるため |

## 2. 性能・拡張性（速さ・データが増えたとき）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 画面の表示・操作の速さ | 画面の表示や保存の結果を、**3秒以内**に表示する | 待たされている感じがしない目安 |
| 同時に使う人数 | **10人**が同時に使っても、上の速さを守る | 講師が数人で確認しても困らないようにするため |
| データの量 | 記録が**1万件**あっても、上の速さを守る | 1日10件記録しても約3年分 |
| 1か月の記録の件数 | 多くても**300件**程度と考え、ページを分けずに全件表示する | 1日10件程度の想定 |
| 機能の追加 | あとから機能（例：グラフ）を追加しやすいように、部品を分けて作る | 余裕があれば機能を追加したいため |

## 3. 運用・保守性（公開したあとの見守り・直しやすさ）

### 3-1. 公開と費用

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 公開する期間 | 提出してから、**講師の確認が終わるまで** | 費用がかかり続けないようにするため |
| 公開が終わったら | AWS のサーバー（EC2）とデータベース（RDS）を**削除**する。プログラムと資料は GitHub に残す | 削除しないと費用がかかり続けるため |
| 費用の上限 | AWS の費用は**月5,000円以内** | 個人で無理なく払える金額 |
| 費用の見張り | AWS の予算の通知機能を使い、**月4,000円を超えそうになったらメール**で知らせる | 上限を超える前に気づけるようにするため |

### 3-2. お試し用データ

| 項目 | 決めたこと | 理由 |
|---|---|---|
| お試し用データ | 本番環境には、お試し用の記録（2〜3か月分）を入れておく | 講師がすぐに一覧や合計を確認できるようにするため |
| データを最初の状態に戻す | 戻すための**ファイルと手順書**を用意し、**手作業**で戻せるようにする | 誰でも操作できるため、データがぐちゃぐちゃになることがあるから |
| 戻すタイミング | 講師に確認をお願いする前と、データがおかしくなったとき | 講師がきれいな状態で確認できるようにするため |

### 3-3. 直しやすさ・記録

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 部品の分け方 | 画面側・処理側・データベースは、フォルダを分けて作る | 途中で課題の条件が変わっても、関係する部品だけを直せばよいようにするため |
| プログラムの説明 | 初心者が読んでも分かるように、日本語で説明（コメント）を書く | あとで自分や講師が読んで分かるようにするため |
| 作業の手順書 | 「自分のパソコンで動かす手順」「AWS に公開する手順」「データを戻す手順」を書く | 時間がたっても、同じ作業をくり返せるようにするため |
| 問題の記録（ログ） | 処理側で問題（エラー）が起きたら、その内容を記録に残す | 止まったときに原因を調べられるようにするため |
| 変更の管理 | 作業は `develop` ブランチで行い、変更のたびに GitHub に記録（コミット）する | いつ何を変えたか分かるようにし、前の状態に戻せるようにするため |

## 4. 移行性（古い仕組みからデータを移すか）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| データの移しかえ | **なし**（新しく作る） | 前に作ったアプリは削除済みで、引きつぐデータがないため |

## 5. セキュリティ（どう守るか）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 通信の暗号化 | アドレスを **`https://`** にして、通信を暗号化する | 今のウェブサイトでは当たり前で、`http://` だとブラウザに警告が出るため |
| ログイン | **しない**（誰でも見られ、誰でも操作できる） | 講師が自由に試せるようにするため |
| 本物のデータ | 本番環境には、本物の家計のデータを**入れない** | 誰でも見られ、操作できるため |
| データベースへの接続 | データベース（RDS）は、インターネットから直接つなげないようにし、**サーバー（EC2）からだけ**つなげるようにする | データベースを外からの攻撃から守るため |
| サーバーの管理用の入口 | サーバー（EC2）を管理するための入口は、**自分だけ**が使えるようにする | 他人にサーバーを操作されないようにするため |
| 秘密の情報 | データベースのパスワードなどは、**GitHub に上げない**（専用のファイルに分けて書く） | GitHub は公開しているため、上げると誰でも見られてしまうから |
| 入力のチェック | 画面側と処理側の**両方**でチェックする | 画面側のチェックは、詳しい人ならすり抜けられるため |
| よくある攻撃への対策 | 入力された文字を「命令」として扱わないようにする（SQL インジェクション対策）<br>画面に表示する文字を、そのまま「プログラム」として動かさないようにする（XSS 対策） | ウェブアプリが狙われやすい、代表的な攻撃を防ぐため。くわしくは [用語集](09_用語集.md) |
| 使う部品（ライブラリ）の安全 | 公開する前に、使っている部品に重大な弱点がないか確認する | 古い部品の弱点をねらった攻撃を防ぐため |

## 6. システム環境（どんな機械・ブラウザで動かすか）

### 6-1. 使う人の環境

| 項目 | 決めたこと |
|---|---|
| パソコンのブラウザ | Google Chrome・Microsoft Edge の最新版 |
| スマートフォンのブラウザ | iPhone の Safari・Android の Chrome の最新版 |
| スマートフォンでの使える度合い | 画面が崩れず、横にはみ出さずに、**すべての操作ができる**こと（パソコンでの使いやすさを優先する） |
| 画面の幅 | パソコンは横幅1280ピクセル、スマートフォンは横幅360ピクセル以上で確認する |

### 6-2. 動かす環境

| 項目 | 決めたこと |
|---|---|
| 本番環境 | AWS の EC2（サーバー）と RDS（データベース）。場所は東京（東京リージョン） |
| 開発の環境 | Windows 11 のパソコン、VS Code |
| 使う技術 | [技術スタック](../02_設計/01_技術スタック.md) を参照 |
| 文字の種類 | 日本語を含むすべての文字を保存できるようにする（文字コード：UTF-8） |

## 7. 使いやすさ（迷わずに使えるか）

| 項目 | 決めたこと |
|---|---|
| 言葉 | 画面の文字・メッセージは、すべて日本語にする |
| 金額の表示 | 3けたごとにカンマを付ける（例：1,000円） |
| 間違いの知らせ方 | どの項目がどう間違っているかを、その項目のすぐ下に日本語で表示する |
| 色の使い方 | 色だけで意味を伝えない（収入・支出は色に加えて文字でも表示する） |
| 操作の手間 | 毎日使う「記録の登録」は、最初の画面から1回押すだけで始められるようにする |

くわしい表示のルールは [画面要件](05-0_画面一覧と共通ルール.md) を参照してください。
