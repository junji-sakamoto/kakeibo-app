# 受け入れ基準（完成の基準）

[要件定義の概要（入口）](00_概要.md) に戻る

何ができたら「完成」として提出するかを決めます。
次のすべてを満たしたら「完成」とし、提出する。

| 番号 | 基準 | 確かめ方 |
|---|---|---|
| 1 | [機能一覧](03_機能一覧.md) のすべての機能が、[画面要件](05-0_画面一覧と共通ルール.md) のとおりに動く | [機能試験](../04_試験/01_機能試験.md) の確認項目で確かめる |
| 2 | [画面遷移図](../02_設計/02_画面遷移図.md) のすべての遷移が、図と表のとおりに動く | [画面遷移試験](../04_試験/02_画面遷移試験.md) で遷移1〜22を1つずつ確かめる |
| 3 | 試験の資料に書いた確認項目が、すべて合格している | [試験結果のまとめ](../04_試験/04_試験結果のまとめ.md) で確かめる |
| 4 | [非機能要件](07_非機能要件.md) の決まりごとを満たしている | [非機能試験](../04_試験/03_非機能試験.md) で1行ずつ確かめる |
| 5 | 本番環境（AWS）が `https://` のアドレスで動いていて、講師が開ける。そのアドレスが GitHub の README に書いてある | 自分のパソコンとスマートフォンで開いて確かめる |
| 6 | GitHub の `main` ブランチに、資料とプログラムがすべて入っている（`develop` を `main` に取りこんだ） | GitHub の画面で確かめる |

- すべてを満たしたら、GitHub の URL（`https://github.com/junji-sakamoto/kakeibo-app`）を講師に提出する
