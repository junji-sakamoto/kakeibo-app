## 1. 背景・目的

### 背景

- スクールの課題として、画面側・処理側・データベースを持つウェブアプリを作り、AWS に公開する必要がある
- 身近で分かりやすい題材として、家計簿アプリを選んだ

### 目的

- 毎日の収入と支出を記録し、月ごとにお金の流れを確認できるようにする
- 開発を通して、要件定義 → 設計 → 実装 → 試験（テスト）→ 公開 の流れを一通り経験する

## 2. 使う人

- 自分1人で使う（ログイン機能は作らない）
- スクールの講師が確認できるように、本番環境は**誰でも見られる状態で公開する**
  - そのため、本番環境には本物の家計のデータは入れず、**お試し用のデータだけ**を入れる

## 3. 利用の流れ

使う人が、どんな順番でアプリを操作するかをまとめます。

### 3-1. 毎日の記録

```
① アプリを開く
   → 今月の記録の一覧と、今月の合計（収入・支出・差額）が表示される
② 「登録」ボタンを押す
③ 日付・種類（収入／支出）・カテゴリ・金額・メモを入力して保存する
   → 一覧と合計に、すぐ反映される
```

### 3-2. 記録の修正・削除

```
① 一覧から、直したい記録の「修正」または「削除」ボタンを押す
② 修正：内容を直して保存する
   削除：「本当に削除しますか？」で「はい」を押す
   → 一覧と合計に、すぐ反映される
```

### 3-3. 過去の月を見る

```
① 月を選ぶ（前の月・次の月に切り替える）
   → その月の記録の一覧と合計が表示される
```

### 3-4. カテゴリの管理

```
① カテゴリ管理の画面を開く
② カテゴリを登録・修正・削除する
   → 記録を登録するときの選択肢に反映される
```

## 4. 機能に関する決まりごと（機能要件）

### 4-1. 機能の一覧

| 番号 | 区分 | 機能 | 内容 |
|---|---|---|---|
| 機能1 | 記録 | 記録の登録 | 収入・支出を1件登録する |
| 機能2 | 記録 | 記録の一覧 | 登録した記録を一覧で見る |
| 機能3 | 記録 | 記録の修正 | 登録した記録を直す |
| 機能4 | 記録 | 記録の削除 | 登録した記録を消す |
| 機能5 | 集計 | 月ごとの合計 | 選んだ月の収入合計・支出合計・差額（残り）を表示する |
| 機能6 | カテゴリ | カテゴリの登録 | 新しいカテゴリを追加する |
| 機能7 | カテゴリ | カテゴリの一覧 | カテゴリを一覧で見る |
| 機能8 | カテゴリ | カテゴリの修正 | カテゴリの名前を直す |
| 機能9 | カテゴリ | カテゴリの削除 | カテゴリを消す |

作る順番：記録（機能1〜4）→ 月ごとの合計（機能5）→ カテゴリ（機能6〜9）

### 4-2. 記録のルール（機能1〜4）

1件の記録には、次の項目を入れます。

| 項目 | 必須 | ルール |
|---|---|---|
| 日付 | 必須 | 年・月・日 |
| 種類 | 必須 | 「収入」か「支出」のどちらか |
| カテゴリ | 必須 | 種類に合ったカテゴリから選ぶ |
| 金額 | 必須 | 1円以上の整数（円） |
| メモ | 任意 | 100文字まで |

- 一覧は日付の新しい順に並べる
- 一覧は月を選んで、その月の記録だけを表示する（最初は今月）
- 削除するときは「本当に削除しますか？」と確認する

### 4-3. 月ごとの合計のルール（機能5）

- 選んだ月の「収入の合計」「支出の合計」「差額（収入 − 支出）」を表示する
- 記録の一覧と同じ画面に表示する

### 4-4. カテゴリのルール（機能6〜9）

- カテゴリ（分類）は「収入用」と「支出用」に分ける
  - 支出を登録するときは、支出用のカテゴリだけを選べる
- 同じ種類の中で、同じ名前のカテゴリは登録できない
- カテゴリ名は1〜20文字
- 記録で使われているカテゴリは**削除できない**
  - 「このカテゴリは記録で使われているため削除できません」と表示する
- アプリを使い始めたときに、次のカテゴリを最初から入れておく（あとから修正・削除できる）

| 種類 | 最初から入れておくカテゴリ |
|---|---|
| 収入 | 給料、その他 |
| 支出 | 食費、日用品、交通費、光熱費、その他 |

## 5. 機能以外の決まりごと（非機能要件）

品質や使い心地に関する決まりごとです。

### 5-1. 使える環境

| 項目 | 内容 |
|---|---|
| パソコン | Google Chrome（グーグル・クローム）・Microsoft Edge（マイクロソフト・エッジ）の最新版で使える |
| スマートフォン | 画面が崩れずに最低限の操作ができる（パソコンを優先する） |

### 5-2. 使いやすさ

- 画面の文字・メッセージはすべて日本語にする
- 金額は3けたごとにカンマを付けて表示する（例：1,000円）
- 入力に間違いがあるときは、どの項目がどう間違っているかを日本語で表示する

### 5-3. 速さ

- 画面の表示や、保存などの操作の結果は、3秒以内に表示する

### 5-4. 安全性

- 入力のチェックは、画面側と処理側の両方で行う
- データベースのパスワードなどの秘密の情報は、GitHub に上げない
- データベース（RDS）には、インターネットから直接つなげないようにし、EC2 からだけつなげるようにする
- 誰でも操作できる状態で公開するため、本番環境には本物の家計のデータを入れない（「2. 使う人」を参照）

### 5-5. 運用

- AWS の費用は、月5,000円以内に収める（仮）
- データベースは、RDS の自動の控え（バックアップ）を使う

### 5-6. 直しやすさ

- 画面側・処理側・データベースは、フォルダを分けて作る
  - 途中で課題の条件が変わっても、関係する部品だけを直せばよいようにする
- プログラムには、初心者が読んでも分かるように日本語で説明（コメント）を書く

## 6. 作らないもの

- ログイン機能（使うのは自分1人のため）
- カテゴリ別の集計・グラフ（余裕があれば、あとで追加を検討する）

## 7. あとで決めること

- 文字数・金額の上限などの細かい数字（今の数字は仮。設計で見直してよい）
- AWS の費用の上限（今は仮で月5,000円）
- 本番環境のアドレスを、通信を暗号化する `https://` にするかどうか（構成設計で決める）
