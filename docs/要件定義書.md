## 1. 概要

収入と支出を記録し、月ごとの合計を確認できる、ウェブブラウザで使う家計簿アプリを作る。
画面側（フロントエンド）・処理側（バックエンド）・データベースの3つの部品で作り、AWS に公開する。

## 2. 背景・目的

### 2-1. 背景

- スクールで、ウェブアプリの作り方（画面・処理・データベース・公開）を学んできた
- その学習のまとめとして、スクールから「家計簿アプリを作って提出する」課題が出された
- 課題には「React・Java・PostgreSQL などを使わず、代わりのものを使う」「AWS の EC2 と RDS に公開する」といった条件がある（くわしくは [課題の条件と使う技術](課題の条件と使う技術.md)）

### 2-2. 目的

このアプリを作る一番の目的は**学習**です。

| 番号 | 目的 | 具体的には |
|---|---|---|
| 1 | システム開発の流れを一通り経験する | 要件定義 → 設計 → 実装 → 試験 → 公開 を、資料を作りながら順番に進める |
| 2 | 3つの部品に分けて作る方法を身につける | 画面側・処理側・データベースを分けて作り、それぞれのつながり方を理解する |
| 3 | 授業で使った技術とは別の技術を、自分で調べて使えるようになる | React の代わりに Vue.js、Java の代わりに Node.js、PostgreSQL の代わりに MySQL を使う |
| 4 | インターネットに公開する方法を身につける | AWS の EC2 と RDS を使って、誰でも見られる状態で公開する |
| 5 | 実際に使える家計簿アプリを完成させる | 収入と支出を記録し、月ごとの合計を確認できる |

### 2-3. 達成できたと言える状態

- 講師が、公開したアドレスを開いて、すべての機能を試せる
- 講師が、GitHub で資料とプログラムを読んで、作った流れと仕組みが分かる

## 3. 作る範囲

### 3-1. 作るもの

| 区分 | 内容 |
|---|---|
| アプリ | 記録の登録・一覧・修正・削除、月ごとの合計、カテゴリの登録・一覧・修正・削除 |
| 公開の環境 | AWS（EC2・RDS）での本番環境 |
| 資料 | 要件定義書、設計書、試験の資料、手順書（起動・公開・データの戻し方） |

### 3-2. 作らないもの

| 内容 | 作らない理由 |
|---|---|
| ログイン機能 | 使うのは自分1人で、講師が自由に試せるようにするため |
| カテゴリ別の集計・グラフ | 課題の範囲を絞るため（余裕があれば、あとで検討する） |
| 複数の人で家計簿を分ける機能 | 自分1人で使うため |
| データの書き出し・読み込み（CSV など） | 課題の範囲を絞るため |

## 4. 使う人

| 使う人 | 使い方 |
|---|---|
| 自分 | 開発中に、自分のパソコンで動かして使う |
| スクールの講師 | 提出後に、公開したアドレスを開いて機能を試す |

- 本番環境は**誰でも見られ、誰でも操作できる状態**で公開する
- そのため、本番環境には本物の家計のデータは入れず、**お試し用のデータだけ**を入れる

## 5. 利用の流れ

使う人が、どんな順番でアプリを操作するかをまとめます。画面のくわしい内容は [画面仕様](要件定義/画面仕様.md) を参照してください。

### 5-1. 毎日の記録

```
① アプリを開く
   → 「記録一覧画面」に、今月の記録と、今月の合計（収入・支出・差額）が表示される
② 「登録」ボタンを押す → 「記録入力画面」に切り替わる
③ 日付・種類（収入／支出）・カテゴリ・金額・メモを入力して「保存」を押す
   → 「記録一覧画面」に戻り、一覧と合計に反映される
```

### 5-2. 記録の修正・削除

```
① 「記録一覧画面」で、直したい記録の「修正」または「削除」ボタンを押す
② 修正：「記録入力画面」で内容を直して「保存」を押す
   削除：「この記録を削除しますか？」で「OK」を押す
   → 一覧と合計に反映される
```

### 5-3. 過去の月を見る

```
① 「記録一覧画面」で「◀ 前の月」「次の月 ▶」を押す
   → その月の記録と合計が表示される
```

### 5-4. カテゴリの管理

```
① 画面上の「カテゴリ」を押す → 「カテゴリ一覧画面」に切り替わる
② 「登録」「修正」→「カテゴリ入力画面」で入力して保存する
   「削除」→ 確認のあと削除する（記録で使われているカテゴリは削除できない）
   → 記録を入力するときの選択肢に反映される
```

## 6. 前提条件・制約条件

### 6-1. 前提条件（この要件定義書が成り立つための前提）

- 開発は自分1人で行う
- 提出期限は特にない
- 公開期間中の AWS の費用は、自分で支払う

### 6-2. 制約条件（守らなければいけない条件）

- スクールの課題の条件を守る（[課題の条件と使う技術](課題の条件と使う技術.md) を参照）
- AWS の費用は月5,000円以内に収める（くわしくは [非機能要件](要件定義/非機能要件.md)）

## 7. 完成の基準（受け入れの基準）

次のすべてを満たしたら「完成」とし、提出する。

| 番号 | 基準 |
|---|---|
| 1 | [機能要件](要件定義/機能要件.md) のすべての機能が、[画面仕様](要件定義/画面仕様.md) のとおりに動く |
| 2 | 試験の資料に書いた確認項目が、すべて合格している |
| 3 | [非機能要件](要件定義/非機能要件.md) の決まりごとを満たしている |
| 4 | 本番環境（AWS）に `https://` のアドレスで公開され、講師が開ける |
| 5 | GitHub の `develop` ブランチに、資料とプログラムがすべて入っている |
