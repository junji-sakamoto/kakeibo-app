# スケジュール

提出期限は特にないため、日付は決めずに**作業の順番**と**進み具合**を管理します。
終わった作業は「状態」を「完了」に書き換えます。

| 順番 | 工程 | やること | 作るもの | 状態 |
|---|---|---|---|---|
| 1 | 準備 | GitHub の保存場所（リポジトリ）と作業用ブランチ（develop）を作る | リポジトリ | 完了 |
| 2 | 要件定義 | 課題の条件・使う技術・機能・画面仕様・非機能要件を決める | [課題の条件と使う技術](課題の条件と使う技術.md)、[要件定義書](要件定義書.md) | 確認中 |
| 3 | 基本設計 | 画面遷移図（画面のつながり） | [画面遷移図](設計/画面遷移図.md) | 確認中 |
| 4 | 基本設計 | ER図（データの形とつながり） | [ER図](設計/ER図.md) | 確認中 |
| 5 | 基本設計 | データの流れの図 | データの流れの図 | これから |
| 6 | 基本設計 | 画面設計（色・大きさなどの見た目） | 画面設計 | これから |
| 7 | 技術選定 | 設計をもとに、使う技術を正式に決める | [技術選定書](設計/技術選定書.md) | データベースだけ決定 |
| 8 | 詳細設計 | テーブルの細かい定義（データベース設計） | [テーブル定義書](設計/テーブル定義書.md) | 確認中 |
| 9 | 詳細設計 | 画面側と処理側のやりとりの決まりごと（API）の設計 | API 設計書 | これから |
| 10 | 詳細設計 | 全体の組み立ての設計（フォルダの分け方、AWS での動かし方） | 構成設計書 | これから |
| 11 | 実装 | データベースを作る（自分のパソコン） | `database/` フォルダ、[データベースの手順書](手順書/データベースの手順書.md) | 確認中 |
| 12 | 実装 | 処理側を作る（記録 → 月ごとの合計 → カテゴリ） | `backend/` フォルダ | これから |
| 13 | 実装 | 画面側を作る（記録 → 月ごとの合計 → カテゴリ） | `frontend/` フォルダ | これから |
| 14 | 試験 | 機能が要件どおりに動くか確かめる（テスト） | 試験の資料 | これから |
| 15 | 公開 | AWS（EC2・RDS）に公開する | 本番環境 | これから |
| 16 | 提出 | GitHub のアドレスを提出する | — | これから |

## 進め方のルール

- 1つの工程が終わるごとに、動きや内容を確認してから記録（コミット）する
- 作業は `develop` ブランチで行う
