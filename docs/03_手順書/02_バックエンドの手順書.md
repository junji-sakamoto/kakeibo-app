# バックエンドの手順書（自分のパソコン）

自分のパソコンで、処理側（バックエンド）を動かす手順です。
コマンドは、VS Code の画面下のターミナル（PowerShell）で入力します。

> 使っている技術は [技術スタック](../02_設計/01_技術スタック.md)、API の決まりごとは [API 設計書](../02_設計/06_API設計書.md) を参照してください。

## 0. 関係するファイル

```
backend/
├── package.json        ← このプログラムの説明書（使う部品と、その版）
├── .npmrc              ← 部品を入れるときの決まり（Node.js の版が違えば止める、版を細かく固定する）
├── eslint.config.js    ← 書き方のチェック（LINT）の決まり
├── package-lock.json   ← 部品の細かい版の記録（npm が自動で作る。手で直さない）
├── .env.example        ← 設定の見本（GitHub に上げる）
├── .env                ← 本物の設定（パスワードを含むので GitHub に上げない）
├── node_modules/       ← 入れた部品の置き場所（GitHub に上げない。npm install で作り直せる）
└── src/                ← プログラム本体
    ├── server.js       ← 起動する入口
    ├── app.js          ← API の組み立て（どのお願いを、どこで受けるか）と、共通のエラー処理
    ├── db.js           ← データベースとのつなぎ方
    ├── validation.js   ← 入力のチェック
    └── routes/         ← API ごとのプログラム
        ├── health.js   ← API11（動いているかの確認）
        ├── records.js  ← API1〜5（記録）
        └── categories.js ← API6〜10（カテゴリ）
```

## 1. はじめての準備（1回だけ）

1. Node.js 26 系の長期サポート版（LTS）が入っていることを確かめる

   ```powershell
   node -v
   ```

   `v26.` で始まる版が表示されれば大丈夫です（使っている版は [開発環境と版の一覧](00_開発環境と版の一覧.md)）。違う版のときは、`npm install` が `EBADENGINE` というエラーで止まります。

2. 部品を入れる（`backend` フォルダで実行）

   ```powershell
   cd backend
   npm install
   ```

3. `backend/.env.example` をコピーして、同じ場所に `backend/.env` という名前で置く
4. `backend/.env` の `DB_PASSWORD` を、`database/.env` の `MYSQL_PASSWORD` と同じ値に書き換える

## 2. 起動する

**先にデータベースを起動しておきます**（[データベースの手順書](01_データベースの手順書.md) の「2. 起動する」）。そのあと、`backend` フォルダで次のどちらかを実行します。

| コマンド | 使うとき |
|---|---|
| `npm start` | ふつうに起動する |
| `npm run dev` | プログラムを直しながら使う（ファイルを保存するたびに、自動で起動し直す） |

`処理側を起動しました：http://127.0.0.1:3000` と表示されれば、起動できています。

## 3. 止める

起動したターミナルで `Ctrl + C` を押します。

## 4. 動いているかを確かめる

処理側を起動したまま、**別のターミナル**を開いて次のコマンドを実行します。

```powershell
Invoke-WebRequest http://127.0.0.1:3000/api/health -SkipHttpErrorCheck | Select-Object StatusCode, Content
```

| 結果 | 意味 |
|---|---|
| `200` `{"status":"ok"}` | 処理側もデータベースも動いている |
| `500` `{"message":"S04"}` | 処理側は動いているが、データベースにつながらない（データベースが起動しているか確かめる） |
| エラー（接続できません） | 処理側が起動していない |

ブラウザで `http://127.0.0.1:3000/api/health` を開いても確かめられます。

## 5. 試験（テスト）を行う

API が [API 設計書](../02_設計/06_API設計書.md) のとおりに動くかを、自動で確かめます。**先にデータベースを起動しておきます**（処理側は起動しなくて大丈夫です。試験のプログラムが自分で起動します）。

```powershell
cd backend
npm test
```

- 最後に `ℹ fail 0` と表示されれば、すべて合格です
- 試験は、お試しデータに影響しないように、**2099年11月・12月の日付**と、**名前が「試験用」で始まるカテゴリ**だけを使います。作った記録とカテゴリは、最後に全部削除します
- 試験のプログラムは `backend/tests/` にあります（`records.test.js`：記録の API、`categories.test.js`：カテゴリの API）

## 6. 書き方のチェック（LINT）を行う

```powershell
cd backend
npm run lint
```

何も表示されなければ合格です。全体の品質チェックは [品質チェックの手順書](04_品質チェックの手順書.md) を参照してください。

## 7. 困ったとき

| 表示 | 原因と直し方 |
|---|---|
| `.env に次の設定がありません` | `backend/.env` がない、または書き忘れがある。「1. はじめての準備」の3・4を行う |
| `address already in use` | すでに別のターミナルで起動している。そちらを `Ctrl + C` で止める |
| `Cannot find package 'express'` | 部品が入っていない。`backend` フォルダで `npm install` を行う |
