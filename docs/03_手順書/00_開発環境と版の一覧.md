# 開発環境と版の一覧

このアプリを作るのに使っている**道具と部品の版（バージョン）**を、ここにまとめます。
版が変わると動きが変わることがあるため、**どの版で作り、確かめたか**を記録しておきます。

> 「なぜその技術を選んだか」は [技術スタック](../02_設計/01_技術スタック.md) を参照してください。この資料には、**実際に使っている細かい版**だけを書きます。

## 1. 版の管理のしかた

| 決まり | 内容 |
|---|---|
| 細かい版まで固定する | プログラムの部品やデータベースは、「8.4.13」のように細かい版まで書いて固定する。作り直しても、同じ版になるようにするため |
| 固定する場所 | 下の表の「固定している場所」に書いたファイル。**版を変えるときは、そのファイルとこの資料の両方を直す** |
| 版を上げるとき | 「5. 版を上げるときの手順」のとおりに行い、「6. 変更の記録」に書き残す |
| 自分のパソコンと本番環境 | できるだけ同じ版にそろえる（違うと、自分のパソコンでは動いたのに本番では動かない、ということが起きるため） |

## 5. 版を上げるときの手順

1. 上げる理由を決める（例：弱点の修正が出た、長期サポート版が新しくなった）
2. 固定している場所のファイルを書き換える（部品なら `npm install 部品の名前@新しい版`）
3. 動かして確かめる
   - データベース：[データベースの手順書](01_データベースの手順書.md) の「5. 決まりどおりに動くか確かめる」
   - 処理側：[バックエンドの手順書](02_バックエンドの手順書.md) の「4. 動いているかを確かめる」
4. この資料の表と、「6. 変更の記録」を直す
5. コミットする（コミットの説明に、何を何から何に上げたかを書く）

部品に弱点がないかは、`backend` フォルダと `frontend` フォルダで、それぞれ次のコマンドを実行すると確かめられます（[非機能要件](../01_要件定義/07_非機能要件.md) の「使う部品の安全」）。

```powershell
npm audit
```
