# データベースの手順書（自分のパソコン）

自分のパソコンで、Docker を使って MySQL（データベース）を動かす手順です。
コマンドは、VS Code の画面下のターミナル（PowerShell）で、**プロジェクトの一番上のフォルダ**（`syokyu-kadai`）にいる状態で入力します。

> テーブルの決まりは [テーブル定義書](../02_設計/04_テーブル定義書.md) を参照してください。

## 0. 関係するファイル

```
database/
├── compose.yaml                  ← Docker の設定（MySQL 8.4 を動かす）
├── .env.example                  ← パスワードなどの見本（GitHub に上げる）
├── .env                          ← 本物のパスワード（GitHub に上げない）
├── sql/                          ← 最初に起動したとき、番号順に自動で実行される
│   ├── 01_create_tables.sql      ← テーブルを作る
│   ├── 02_insert_categories.sql  ← 最初のカテゴリを入れる
│   └── 03_insert_sample_records.sql ← お試し用の記録を入れる（最近3か月分）
├── reset/
│   └── reset_data.sql            ← データを空にする（お試しデータを戻すときに使う）
└── tests/
    └── check_rules.sql           ← 決まりどおりに動くかを確かめる
```

## 1. はじめての準備（1回だけ）

1. **Docker Desktop を起動する**（Windows のスタートメニューから。画面左下が緑色になれば準備完了）
2. `database/.env.example` をコピーして、同じ場所に `database/.env` という名前で置く
3. `database/.env` を開き、2か所の「ここに〜のパスワード」を、自分で決めたパスワードに書き換える（英字と数字で20文字くらい）

> `.env` は `.gitignore` で除外しているので、GitHub には上がりません。

## 2. 起動する

```powershell
docker compose -f database/compose.yaml up -d --wait
```

- 最後に `Container kakeibo-db Healthy` と出れば、起動できています
- **はじめて起動したとき**だけ、`sql` フォルダの SQL が番号順に実行され、テーブル・最初のカテゴリ・お試しデータが入ります

## 3. 止める

```powershell
docker compose -f database/compose.yaml down
```

- 止めても、データは消えません。次に起動すると、続きから使えます

## 4. 中身を見る（SQL を実行する）

```powershell
docker exec -it kakeibo-db sh -c 'mysql --default-character-set=utf8mb4 -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"'
```

- `mysql>` と出たら、SQL を入力できます。例：

```sql
SELECT * FROM categories;
```

- 終わるときは `exit` と入力します

> **注意**：`--default-character-set=utf8mb4` を付け忘れると、日本語が「??」と表示されます。データが壊れたわけではなく、**表示の設定**の問題です。

## 5. 決まりどおりに動くか確かめる

```powershell
docker cp database/tests/check_rules.sql kakeibo-db:/tmp/check_rules.sql
docker exec kakeibo-db sh -c 'mysql -t --force --default-character-set=utf8mb4 -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" < /tmp/check_rules.sql'
```

- 確認1〜18の結果が表示されます。それぞれの「（〜なら合格）」と見比べます
- 最後に取り消しをするので、データベースの中身は変わりません

## 6. お試しデータを最初の状態に戻す

データがぐちゃぐちゃになったときや、講師に確認をお願いする前に使います。

```powershell
docker cp database/reset/reset_data.sql kakeibo-db:/tmp/reset_data.sql
docker exec kakeibo-db sh -c 'M="mysql --default-character-set=utf8mb4 -u$MYSQL_USER -p$MYSQL_PASSWORD $MYSQL_DATABASE"; $M < /tmp/reset_data.sql && $M < /docker-entrypoint-initdb.d/02_insert_categories.sql && $M < /docker-entrypoint-initdb.d/03_insert_sample_records.sql'
```

やっていること：

1. `reset_data.sql` で、記録とカテゴリを全部消し、番号を 1 から付け直す
2. `02_insert_categories.sql` で、最初のカテゴリを入れ直す
3. `03_insert_sample_records.sql` で、お試し用の記録（**実行した日から見て**最近3か月分）を入れ直す

> 本番環境（AWS の RDS）では、同じ SQL を `.\infra\deploy.ps1 -ResetData` で実行します（[AWS への公開の手順書](07_AWSへの公開の手順書.md) の 5章）。

## 7. テーブルの形を変えたとき（作り直す）

`sql` フォルダの SQL を直したときは、データベースを**作り直す**必要があります（SQL が自動で実行されるのは、はじめて起動したときだけのため）。

```powershell
docker compose -f database/compose.yaml down -v
docker compose -f database/compose.yaml up -d --wait
```

- `-v` を付けると、**データも全部消えます**。お試し用データは SQL から自動で入り直します

## 8. 使い終わったら（すべて消す）

課題が終わって、もう使わないときの手順です。

```powershell
docker compose -f database/compose.yaml down -v --rmi all
```

- データベース・データ・ダウンロードした MySQL の部品が、すべて消えます
