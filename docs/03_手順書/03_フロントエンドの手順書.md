# フロントエンドの手順書（自分のパソコン）

自分のパソコンで、画面側（フロントエンド）を動かす手順です。
コマンドは、VS Code の画面下のターミナル（PowerShell）で入力します。

> 使っている技術は [技術スタック](../02_設計/01_技術スタック.md)、細かい版は [開発環境と版の一覧](00_開発環境と版の一覧.md)、画面の決まりは [画面要件](../01_要件定義/05-0_画面一覧と共通ルール.md) を参照してください。

## 0. 関係するファイル

```
frontend/
├── package.json        ← このプログラムの説明書（使う部品と、その版）
├── package-lock.json   ← 部品の細かい版の記録（npm が自動で作る。手で直さない）
├── .npmrc              ← 部品を入れるときの決まり（Node.js の版が違えば止める、版を細かく固定する）
├── vite.config.js      ← Vite の設定（/api へのお願いを処理側に中継する）
├── eslint.config.js    ← 書き方のチェック（LINT）の決まり
├── playwright.config.js ← E2E 試験（Playwright）の設定
├── e2e/                ← E2E 試験のプログラム（records・categories・yearly・common）
├── index.html          ← 画面の入れ物
├── node_modules/       ← 入れた部品の置き場所（GitHub に上げない）
├── dist/               ← 公開用に組み立てたファイル（GitHub に上げない。npm run build で作る）
└── src/                ← プログラム本体
    ├── main.js         ← 入口
    ├── App.vue         ← すべての画面に共通する部分（ヘッダー・お知らせ・確認の窓）
    ├── router.js       ← どのアドレスで、どの画面を出すか
    ├── api.js          ← 処理側とのやりとり（API1〜10）
    ├── messages.js     ← 画面に表示する文章（メッセージ一覧と同じ番号）
    ├── format.js       ← 日付・金額の表示のしかた、入力のチェックの道具
    ├── store.js        ← お知らせと確認の窓
    ├── style.css       ← 見た目（画面モックの style.css から写した）
    ├── components/
    │   └── ConfirmDialog.vue ← 削除の確認の窓
    └── views/          ← 画面ごとのプログラム
        ├── RecordList.vue    ← 画面1 記録一覧画面
        ├── RecordForm.vue    ← 画面2 記録入力画面（登録・修正）
        ├── CategoryList.vue  ← 画面3 カテゴリ一覧画面
        ├── CategoryForm.vue  ← 画面4 カテゴリ入力画面（登録・修正）
        └── NotFound.vue      ← 存在しないページ
```

## 1. はじめての準備（1回だけ）

`frontend` フォルダで、部品を入れます。

```powershell
cd frontend
npm install
```

## 2. 起動する

画面側は、処理側（バックエンド）にお願いを送って動くので、**3つを順番に起動**します。

| 順番 | 起動するもの | 手順 |
|---|---|---|
| 1 | データベース | [データベースの手順書](01_データベースの手順書.md) の「2. 起動する」 |
| 2 | 処理側（バックエンド） | [バックエンドの手順書](02_バックエンドの手順書.md) の「2. 起動する」（ターミナルを1つ使う） |
| 3 | 画面側（フロントエンド） | **別のターミナル**を開いて、下のコマンドを実行する |

```powershell
cd frontend
npm run dev
```

`Local: http://127.0.0.1:5173/` と表示されたら、ブラウザで **http://127.0.0.1:5173/** を開きます。

- プログラムや見た目のファイルを保存すると、ブラウザの画面に**すぐに反映**されます
- 画面側から `/api/…` に送ったお願いは、Vite が処理側（3000番）に中継します

## 3. 止める

画面側と処理側を起動したターミナルで、それぞれ `Ctrl + C` を押します。

## 4. 公開用に組み立てる

```powershell
cd frontend
npm run build
```

- `frontend/dist/` に、公開用の軽いファイルができます（AWS に公開するときに使います）
- 書き方の間違いがあると、ここでエラーになるので、間違いを見つけるのにも使えます

## 5. 書き方のチェック（LINT）を行う

```powershell
cd frontend
npm run lint
```

何も表示されなければ合格です。全体の品質チェックは [品質チェックの手順書](04_品質チェックの手順書.md) を参照してください。

## 6. E2E 試験（画面を操作する試験）を行う

**先にデータベースを起動しておきます**。処理側・画面側は、動いていなければ試験の道具が自動で起動し、終わったら止めます。

```powershell
cd frontend
npm run test:e2e
```

- パソコンの **Edge と Chrome** の両方で、同じ試験を行います（ブラウザのダウンロードは要りません）
- 最後に `86 passed` のように表示され、`failed` がなければ合格です
- 失敗したときは、`frontend/e2e-report/index.html` をブラウザで開くと、失敗した画面の写真や操作の記録を見られます
- 試験の中身と結果は [試験計画書](../04_試験/00_試験計画書.md) を参照してください

## 7. 困ったとき

| 表示・様子 | 原因と直し方 |
|---|---|
| 画面の上に「サーバーとの通信に失敗しました。」と出る | 処理側が起動していない。[バックエンドの手順書](02_バックエンドの手順書.md) の「2. 起動する」を行う |
| 画面の上に「予期しないエラーが発生しました。」と出る | データベースが起動していない可能性がある。[データベースの手順書](01_データベースの手順書.md) の「2. 起動する」を行う |
| `Port 5173 is already in use` | すでに別のターミナルで画面側を起動している。そちらを使うか、`Ctrl + C` で止める |
| `EBADENGINE` | Node.js の版が 26 系ではない。[開発環境と版の一覧](00_開発環境と版の一覧.md) を見て、版を合わせる |
