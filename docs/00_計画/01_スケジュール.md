# スケジュール

提出期限は特にないため、日付は決めずに**作業の順番**と**進み具合**を管理します。
終わった作業は「状態」を「完了」に書き換えます。

| 順番 | 工程 | やること | 作るもの | 状態 |
|---|---|---|---|---|
| 1 | 準備 | GitHub の保存場所（リポジトリ）と作業用ブランチ（develop）を作る | リポジトリ | 完了 |
| 2 | 要件定義 | 課題の条件・機能・画面要件・非機能要件などを決める | [要件定義書](../../要件定義書.md) | 確認中 |
| 3 | 基本設計 | 画面遷移図（画面のつながり） | [画面遷移図](../02_設計/02_画面遷移図.md) | 確認中 |
| 4 | 基本設計 | ER図（データの形とつながり） | [ER図](../02_設計/03_ER図.md) | 確認中 |
| 5 | 基本設計 | データの流れの図 | [データの流れ](../02_設計/05_データの流れ.md) | 確認中 |
| 6 | 基本設計 | 画面設計（色・大きさなどの見た目） | [画面モック](../../mock/index.html)（モックを画面設計とする） | 完了 |
| 7 | 技術選定 | 設計をもとに、使う技術を正式に決める | [技術スタック](../02_設計/01_技術スタック.md) | 確認中 |
| 8 | 詳細設計 | テーブルの細かい定義（データベース設計） | [テーブル定義書](../02_設計/04_テーブル定義書.md) | 確認中 |
| 9 | 詳細設計 | 画面側と処理側のやりとりの決まりごと（API）の設計 | [API 設計書](../02_設計/06_API設計書.md) | 確認中 |
| 10 | 詳細設計 | 全体の組み立ての設計（AWS での動かし方） | [構成設計書](../02_設計/07_構成設計書.md) | 確認中 |
| 11 | 実装 | データベースを作る（自分のパソコン） | `database/` フォルダ、[データベースの手順書](../03_手順書/01_データベースの手順書.md) | 確認中 |
| 12 | 実装 | 処理側を作る（API11 → 記録 → 月ごとの合計 → カテゴリ → 年ごとの合計） | `backend/` フォルダ、[バックエンドの手順書](../03_手順書/02_バックエンドの手順書.md) | 完了（API1〜12、試験40件すべて合格。2026年11月7日に API1 へ繰越を追加） |
| 13 | 実装 | 画面側を作る（記録 → 月ごとの合計 → カテゴリ → 年ごとの合計） | `frontend/` フォルダ、[フロントエンドの手順書](../03_手順書/03_フロントエンドの手順書.md) | 確認中（5つの画面ができ、動作を確認ずみ） |
| 14 | 試験 | 機能が要件どおりに動くか確かめる（テスト） | [試験計画書](../04_試験/00_試験計画書.md)、[試験結果のまとめ](../04_試験/04_試験結果のまとめ.md) | 自分のパソコンでの試験は完了（本番環境での試験が残っている） |
| 15 | 本番環境 | AWS（EC2・RDS）の本番環境を、AWS CLI と Terraform で作り、アプリを載せる | `infra/` フォルダ、[構成設計書](../02_設計/07_構成設計書.md)、[AWS への公開の手順書](../03_手順書/07_AWSへの公開の手順書.md) | 完了（作り方を確かめたあと消してある。提出のときに作り直して公開する） |
| 16 | 提出 | `develop` を `main` ブランチに取りこみ（マージ）、GitHub の URL を講師に提出する | `main` ブランチ | これから |

## 進め方のルール

- 1つの工程が終わるごとに、動きや内容を確認してから記録（コミット）する
- 作業は `develop` ブランチで行う（機能ごとに `feature/…` ブランチを作り、Issue と PR にまとめて `develop` に取りこむ）
- 完成したら、`develop` を `main` に取りこんで提出する。`main` には直接コミットしない
